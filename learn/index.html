JSON syntax at a glance

JSON (JavaScript Object Notation) is a text format for representing structured data. An object groups named values inside braces; an array holds an ordered list inside brackets. Both can contain other objects and arrays, which is why an API response can have several levels of nested data.

A small JSON example

{
  "name": "Ada",
  "active": true,
  "roles": ["editor", "reviewer"],
  "profile": { "location": null }
}

Here, name is a string, active is a boolean, roles is an array, and profile is a nested object.

Rules that prevent common errors

  • Put double quotes around every key and every string value.
  • Separate object properties and array items with commas; do not add a comma after the last item.
  • Use JSON values: objects, arrays, strings, numbers, true, false, and null.
  • JSON has no comments, undefined, or trailing commas.

null, an empty value such as "", and a missing property mean different things. Keep that distinction when reading or validating data.

A practical workflow for working with JSON

  1. Read the structure. Find the outer object or array first, then follow the keys and indexes to the value you need. The JSON basics guide walks through these parts.
  2. Make it readable. Indentation changes how JSON is displayed, not its data. Use the JSON Formatter to expand compact JSON, or the JSON Viewer to explore nested values.
  3. Check syntax before debugging the data. A missing comma or quote makes the whole document invalid. The JSON Validator helps identify syntax errors; a valid document can still have the wrong values or shape for an application.
  4. Check the expected shape when needed. If an API or application requires specific fields and types, describe those requirements with a JSON Schema and validate the data against it.

For hands-on practice, browse the fictional JSON datasets. They include nested records, API response examples, empty arrays, and explicit null values, so you can see how those cases appear in actual JSON.
