Inspect JSON in Tree, Code, or Table View


When an API response or configuration file contains several layers of objects and arrays, a wall of JSON text can be hard to scan. RomitJSON’s online JSON Viewer lets you explore a document as an expandable tree, readable code, or a table when the data has a suitable shape. Search for keys and values, copy a selected node’s path, and keep a copy of the original input for later use.


Paste JSON or open a local .json file, then select View JSON. The viewer parses the input in your browser and reports syntax errors when it cannot read the document. It is designed for inspection; it does not check your data against an API schema or change the original JSON when you switch views.



How to Use the JSON Viewer


    

  1. Paste JSON into the input area, select Open JSON to choose a file, or load the sample to see how the viewer works.
    2. 

  2. Select View JSON to parse the input and show its structure.
    3. 

  3. Choose Tree to expand and collapse nested values, Code to read indented JSON, or Table for a supported list of objects.
    4. 

  4. In Tree view, search for a property name or value. Use the previous and next controls to move between matches.
    5. 

  5. Select a tree node to copy its path, key, or value. Use Copy JSON or Download JSON to keep the original input.

For example, a selected value inside the first user record might have the path $.data.users[0].name. The path shows how to reach that value from the root: data is a property, users[0] is the first array item, and name is a property of that item.

Table view works best when the JSON document’s root is an array of objects, such as a list of products or users. It gathers the object properties into columns and offers column filtering and sorting to help you inspect records. If the document is a single object, an array of primitive values, or a deeply nested response, use Tree or Code instead. Table filtering and sorting affect the view; they do not rewrite the source.



Find a Value in Nested JSON


JSON objects pair property names with values, while arrays hold ordered items. A response can combine both structures, nesting arrays inside objects and objects inside arrays. Expand the relevant branches in Tree view to follow that hierarchy, or search for a distinctive key or value if you already know what you are looking for.


{
  "data": {
    "users": [
      {
        "name": "Asha",
        "address": {
          "city": "Pune"
        }
      }
    ]
  }
}


In this example, the city is under data, then users, the first array item, and address. Its path is $.data.users[0].address.city. Selecting the city node lets you copy its path or value, which can be useful when documenting a response or locating a field in application code.



JSON Viewer, Formatter, and Validator: What’s the Difference?


A JSON viewer helps you explore and navigate data. A formatter focuses on producing indented output, while a validator checks whether the text follows JSON syntax. A valid JSON document can still have the wrong fields or values for your application; checking that requires a schema or application-specific validation.


Use the JSON Formatter when you want formatted output, the JSON Validator when you want to find syntax problems, or JSON Compare to review differences between two documents. For compact output, use the JSON Minifier.



Common JSON Problems


If the viewer cannot parse your input, check the reported error location and look for common syntax issues:


    

  • Single quotes: JSON strings and property names use double quotes.
    • 

  • Trailing commas: Do not leave a comma after the final property or array item.
    • 

  • Missing separators: Add commas between properties or items where required.
    • 

  • Unmatched brackets: Check that every opening brace or bracket has a corresponding closing character.
    • 

  • Comments: Standard JSON does not allow JavaScript-style comments.
    • 



The viewer parses JSON syntax; it cannot determine whether a value is meaningful for your application. For example, it can display a missing email property, but only your requirements or schema can tell you whether that field is required. For the JSON data format itself, see the RFC 8259 specification.



Input Size and Privacy


This viewer accepts input up to 50 MiB. Very large or deeply nested documents can take longer to parse and display. Tree rendering is capped to keep the page responsive, and search checks up to 100,000 values; a search in a very large document may therefore not cover every node. If you only need to read or reformat the full text, try the Code view or the JSON Formatter.


The viewer’s parsing and selected-file reading happen in your browser. Still, avoid pasting passwords, access tokens, private keys, or confidential records into any online tool unless you have confirmed that its handling meets your needs. Read the RomitJSON privacy policy for more information.



Frequently Asked Questions


How do I view a JSON file?
Select Open JSON, choose a .json file, and select View JSON. You can also paste JSON directly into the input box.


Can I search inside nested JSON?
Yes. In Tree view, search keys and values, then use the previous and next controls to move through matches. Expand or select a result to inspect its surrounding structure.


Can I view JSON as a table?
Yes, when the top-level JSON value is an array of objects. The viewer displays object properties as columns. For other shapes, Tree or Code view is more suitable.


Does the JSON Viewer modify my input?
Changing between Tree, Code, and Table views does not edit the source. Copy JSON and Download JSON use the original input; table sorting and filtering are for inspection.


Why does my JSON show a syntax error?
The input may contain invalid JSON syntax, such as single-quoted strings, a trailing comma, a missing comma, or an unmatched bracket. Correct the reported problem and select View JSON again, or use the JSON Validator.


Does valid JSON mean my API data is correct?
No. A JSON viewer can parse and display syntactically valid JSON, but it cannot know whether the fields, types, or values match your API contract. Use a schema or application-specific checks for that.
